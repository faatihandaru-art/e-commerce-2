====================================================================

Header, dan Dashboard yang sudah tampil. Style memakai warna dari
tailwind.config yang sudah ada (vgs-black-void, vgs-blue-electric,

lengkap sebelum menulis kode) dan komponen dari components/ui/ yang
sudah ada (Button, Input, dst -- PAKAI ULANG, jangan bikin versi
baru).

TUGAS KAMU
====================================================================

1. HALAMAN: resources/js/pages/Admin/Product/Create.tsx
   Form untuk menambah produk baru, dibungkus AdminLayout yang
   sudah ada. Berisi:

   a. INFORMASI DASAR
      - Input nama produk (pakai Input dari ui/)
      - Textarea deskripsi
      - Dropdown/select brand (dari props brands)
      - Multi-select atau checkbox group kategori (dari props
        categories, MINIMAL 1 kategori wajib dipilih)
      - Dropdown status (draft/published, atau sesuai enum yang
        dikonfirmasi backend)

   b. UPLOAD GAMBAR (BAGIAN PALING PENTING -- galeri multi-gambar)
      - Input file dengan atribut multiple, terima beberapa gambar
        sekaligus
      - Setelah dipilih, tampilkan PREVIEW thumbnail semua gambar
        yang akan diupload (pakai URL.createObjectURL() dari file
        yang dipilih, browser API bawaan, tidak perlu upload dulu
        ke server untuk preview)
      - User HARUS bisa: menghapus salah satu gambar dari daftar
        sebelum submit, mengubah URUTAN gambar (drag untuk reorder,
        atau tombol naik/turun sederhana jika drag terlalu rumit
        untuk tahap ini), MENANDAI salah satu gambar sebagai gambar
        utama/cover (radio button di bawah tiap thumbnail)
      - Validasi di sisi frontend SEBELUM submit: minimal 1 gambar
        harus dipilih, tampilkan pesan error jelas jika kosong
      - Kirim data file lewat useForm() dari @inertiajs/react --
        PENTING: karena ada file upload, form HARUS dikirim sebagai
        multipart/form-data. Inertia menangani ini otomatis jika kamu
        memasukkan object File langsung ke dalam data useForm(), TAPI
        untuk UPDATE (method PUT/PATCH) dengan file, Laravel/Inertia
        punya keterbatasan dengan FormData -- gunakan pola
        forceFormData: true pada opsi post()/put() jika diperlukan,
        atau method spoofing dengan menambahkan field _method: 'PUT'
        dan tetap memakai post(). Sesuaikan dengan yang benar-benar
        berfungsi, uji dulu sebelum menganggap selesai.

   c. INPUT VARIAN PRODUK
      - Minimal 1 baris varian wajib ada (tampilkan 1 baris kosong
        secara default)
      - Tiap baris varian berisi: SKU (input teks, wajib, harus
        unik), harga (input angka), harga coret/compare_at_price
        (opsional), nama varian jika ada sistem pilihan seperti
        warna/ukuran (untuk tahap ini BOLEH disederhanakan jadi
        satu field teks bebas seperti "Hitam - Wireless" tanpa
        sistem product_options/product_option_values yang lebih
        rumit dari dokumen arsitektur -- CATAT sebagai keterbatasan
        di ringkasan akhir jika disederhanakan begini)
      - Tombol "Tambah Varian" untuk menambah baris baru, tombol
        hapus di tiap baris (kecuali baris terakhir yang tersisa,
        minimal harus ada 1 varian)
      - Validasi: SKU tidak boleh kosong dan tidak boleh duplikat
        ANTAR BARIS DI FORM YANG SAMA (cek di frontend sebelum
        submit), harga harus angka positif

   d. SUBMIT
      - Tombol "Simpan Produk" memakai Button dari ui/ (varian
        primary)
      - Tampilkan state loading saat processing (disable tombol,
        ubah teks jadi "Menyimpan...")
      - Tampilkan error validasi dari backend di bawah field yang
        relevan (errors.name, errors.images, errors['variants.0.sku'],
        dst -- perhatikan Laravel mengirim error array bertingkat
        dengan format seperti ini untuk field array, sesuaikan cara
        membaca errors object dari Inertia)
      - Setelah sukses, redirect otomatis ke halaman index (ini
        akan ditangani otomatis oleh response redirect dari backend)

2. HALAMAN: resources/js/pages/Admin/Product/Edit.tsx
   Form yang SANGAT MIRIP dengan Create.tsx, tapi:
   - Semua field TERISI dengan data produk yang sudah ada (dari
     props product)
   - Galeri gambar menampilkan gambar yang SUDAH TERSIMPAN (dari
     props product.images, sebagai URL lengkap yang bisa langsung
     dipakai di <img src>, BUKAN File object seperti saat create --
     cek dokumentasi backend untuk tahu apakah URL sudah lengkap
     atau perlu disusun sendiri dari path relatif)
   - User bisa MENGHAPUS gambar yang sudah ada (tandai untuk
     dihapus, kirim info ini ke backend saat submit) DAN menambah
     gambar BARU sekaligus dalam satu form yang sama
   - Varian yang sudah ada ditampilkan di baris form yang sudah
     terisi, user bisa edit, hapus, atau tambah baris baru
   - Submit memakai method PUT/PATCH ke route admin.products.update
     (lihat catatan soal file upload + method PUT di atas)

   PERTIMBANGKAN: apakah membuat komponen bersama
   (components/admin/ProductForm.tsx) yang dipakai KEDUA halaman
   Create dan Edit dengan props mode="create" atau mode="edit" untuk
   menghindari duplikasi kode -- ini pendekatan yang LEBIH BAIK
   dibanding menulis dua form terpisah dari nol, karena sebagian
   besar strukturnya identik. Putuskan sendiri berdasarkan seberapa
   mirip kebutuhan keduanya setelah kamu mulai membangun Create.tsx.
